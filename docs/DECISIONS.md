## Backend-A (Foundation, PRD Phases 1–2)

| # | Topic | Decision | Why |
| --- | --- | --- | --- |
| A1 | Local MySQL | `npm run db:local` uses `mysql-memory-server` only to download the official MySQL **8.4.9** macOS arm64 binary (cached in `$TMPDIR/mysqlmsn/binaries`), then runs `mysqld` itself with a persistent data dir `.mysql-data/data` on `127.0.0.1:3307`, user `root`, no password. `--ephemeral` flag falls back to the library's throwaway DB. | The library only supports throwaway databases; persistent data survives restarts. 8.4 LTS ≥ 8.0.16, so CHECK constraints are enforced. |
| A2 | Data dir path | `.mysql-data/data`, not `.mysql-data` itself. | mysqld fails with "Can't create UNDO tablespace … './undo_001' already exists" when the datadir's own name starts with a dot. |
| A3 | Test database | Integration tests reset + seed a separate `dental_test` DB on the same server (`TEST_DATABASE_URL`, default: `DATABASE_URL` with the db renamed). They refuse non-local hosts and DB names without "test". | Tests never clobber dev data. |
| A4 | `db:reset` on remote hosts | Allowed (PRD Phase 11 needs it on the hosted DB) but prints the target and requires `--yes` for any non-localhost host: `DATABASE_URL="…" npm run db:reset -- --yes`. Shell env vars win over `.env.local`. | Prevents wiping the demo DB by accident. |
| A5 | Transaction isolation | `withTransaction` runs at **READ COMMITTED**. | With row locks (Rule 9) serializing writers, READ COMMITTED guarantees the overlap SELECT sees rows committed by the previous lock holder. Under REPEATABLE READ the snapshot could predate the lock (e.g. Rule 10 trying dentist 2 after dentist 1). |
| A6 | Session time zone | Pool sets `timezone: '+08:00'`, `dateStrings: true`, and runs `SET time_zone = '+08:00'` on every new connection; local mysqld also starts with `--default-time-zone=+08:00`. | NF08: `NOW()` (Rule 11 `requested_at = NOW()`) is Manila time even on a UTC host. A fixed offset is exact because Manila has no DST and avoids needing tz tables on Aiven. |
| A7 | Named placeholders | Pool has `namedPlaceholders: true`, so Listing 3.1-style `:appointment_id` works; `?` still works with array params. | Lets the SQL match the paper's listings. |
| A8 | Aiven SSL | `ssl-mode=REQUIRED` (or `sslmode=require`, `ssl=true`) turns TLS on. If `DATABASE_CA_CERT` (PEM) is set the cert is verified; otherwise the connection is encrypted without CA verification. | Aiven uses a per-project CA; the PRD's URL-only setup would fail with strict verification. Set `DATABASE_CA_CERT` on Vercel to harden. |
| A9 | Contact numbers | `normalizeContact` strips spaces, dashes, parentheses, dots; `+63`/`63` → `0`. Valid results: PH mobile `09` + 9 digits (11), landline with area code `0[2-8]` + 7–8 digits (9–10), or local landline `[2-8]` + 6–7 digits (7–8). Everything else → `null` (validation error). Stored digits-only, shown `0917 555 0101` / `(02) 8123 4567`. | PRD asks only for mobile examples; walk-ins may give a landline. A 10-digit number starting `09` (a mistyped mobile) is still rejected. |
| A10 | Past check | `isInPast(date, start)` is true when start ≤ now (Manila). `hasStarted` = same test, used for Rule 7 (`attended`/`no-show` allowed once start time is reached). | Rule 3 says "later than now"; Rule 5 drops starts "at or before" now. |
| A11 | Seed: walk-in timestamps | Walk-ins get `requested_at` = 15 min before the start on the same day, and `reminder_sent_at` NULL. Patients without email also get NULL reminders. All other past rows that were scheduled: `requested_at` 2–5 days before, `reminder_sent_at` 09:00 the day before. | A walk-in booked days ahead (or reminded the day before it existed) would look wrong at the defense; Rule 8 never emails patients without an address. |
| A12 | Seed placement | Extra October rows sit on Oct 1–8 (Mon–Sat) only; Oct 9 onward stays open except the Table 3.6 rows (Oct 12 attended/no-show, Oct 19 scheduled). Reyes always uses Chair 1, Lim Chair 2. The seed asserts no dentist/chair/patient collisions and the Table 3.22 totals before inserting. | PRD Open Question #3; keeps demo days free. |
| A13 | Seed no-shows | Repeat no-shows: Jose Ramos (Oct 2 Reyes, Oct 12 Lim) and Miguel Fernandez (Oct 5 Reyes, Oct 7 Lim); Paolo Garcia has one. Maria Santos has exactly her two Table 3.6 visits (Phase 7 acceptance). | "At least two patients with 2+ no-shows"; threshold 3 → empty list, so "raising the threshold shortens the list". |
| A14 | Seed staff password | `SEED_STAFF_PASSWORD` env, default `ClinicDemo2026!`, bcrypt cost 12. | Change it before seeding the public demo DB. |
| A15 | Session | jose HS256 JWT in cookie `session`: httpOnly, SameSite=Lax, Secure when `NODE_ENV=production`, path `/`, 8 h. Payload: `sub` = user_id, `name`, `email`. Not re-checked against the DB per request (single staff role; logout clears the cookie). | PLAN fixed decision; edge-safe for middleware. |
| A16 | Middleware | Public: pages `/book`, `/book/*`, `/login`; `GET /api/slots`, `POST /api/requests`, `POST /api/auth/login`, `GET /api/cron/reminders`; static files via `config.matcher`. Unauthed pages → 307 `/login?next=<relative path>`; unauthed API → 401 `{"error":"unauthorized"}`. Logged-in visit to `/login` → `next` or `/dashboard`. | PRD API section, method-specific. |
| A17 | CSRF belt-and-braces | Middleware returns 403 for non-GET/HEAD/OPTIONS `/api/*` requests whose `Origin` host differs from `Host`/`X-Forwarded-Host` (cron route exempt). Requests without `Origin` (curl, server-to-server) pass. | SameSite=Lax already blocks most cross-site POSTs; this closes the rest cheaply. |
| A18 | Login timing | Unknown email still runs one bcrypt compare against a cost-12 dummy hash; both failures return 401 `{"error":"invalid_credentials","message":"Invalid email or password"}`. Empty fields return 400 `validation_error`. No rate limiting yet (flag for Security). | PRD Phase 1 acceptance. |
| A19 | `x-pathname` header | Middleware forwards `x-pathname` (path + query) so `requireStaffPage()` can build `/login?next=…` from Server Components. | Server Components can't read the URL otherwise. |

| A22 | Zod | Zod v4 (`zod@4`). Schemas output camelCase fields; `contactNumber` is already normalized; optional texts/emails come out `null` when blank. | One schema for client and route handler. |
| A23 | `Secure` cookie on localhost | `next start` sets `NODE_ENV=production`, so the cookie is `Secure`. Chrome/Playwright accept it on `http://localhost`; Safari may not. Use `npm run dev` for manual local testing in Safari. | Keeps the production default strict. |

## Backend-B (API, PRD Phases 4–9 server side)

| # | Topic | Decision | Why |
| --- | --- | --- | --- |
| B1 | Handler auth | Staff handlers call `requireStaffApi(req)` (lib/http.ts), which verifies the same signed `session` cookie as `requireStaff()` but reads it from the `Request`. | `cookies()` from `next/headers` throws outside a Next request scope, so handlers could not be integration-tested directly; behavior in Next is identical. |
| B2 | Error shape | Every error is `{ error: code, message, ... }`; FK RESTRICT → 409 `in_use` with message "In use by existing appointments"; duplicate contact → 409 `duplicate_contact` with message "Contact number already used by another patient". Unknown errors → logged, generic 500. | One shape for the UI; codes for logic, messages for people; no SQL leaks. |
| B3 | Dashboard grid | Shows pending, scheduled, attended, no-show; hides cancelled and declined. `openSlots` uses the shortest service's duration. Pending rows (no chair) appear in the dentist view and in `unassigned` for the chair view. | A cancelled original of a reschedule would otherwise sit next to its replacement; the dashboard has no service picked. |
| B4 | Summary counts | `todayTotal` = grid rows on the date; `pendingCount` = all pending; `tomorrowCount` = scheduled on date+1 (reminder candidates, without the email filter). | PRD Phase 6 wording. |
| B5 | Reports | Only attended/cancelled/no-show rows count; `total` = attended + cancelled + no-show; cancelled excludes rows some other row's `rescheduled_from_id` points to; rate null when attended + no-show = 0. Repeat no-shows are all-time (not month-scoped). | FR15/FR16; Table 3.22 reproduced (10.0 / 20.0 / 14.3%). |
| B6 | Public form vs existing patient | A matching contact number reuses the patient and does **not** overwrite name/email/birthdate from public input. The confirmation goes to the email on file. | Otherwise anyone who knows a patient's number could change their record or redirect their emails. Staff edit details on the patient page. |
| B7 | Public slot grid | `POST /api/requests` also requires the start to be on the Rule 5 grid (hours start + k × `SLOT_INTERVAL_MINUTES`); off-grid → 409 `slot_taken`. Staff bookings may use any time inside hours. | The public API can't book times the form never offers; staff keep flexibility for walk-ins. |
| B8 | Booking window | Public slots/requests: today..today+60 (Manila), else 400. With a staff session `GET /api/slots` allows up to 366 days. | PRD Phase 4; staff may book further ahead. |
| B9 | Rule 9/10 locks | Lock order everywhere: dentist(s) ascending id → chair → appointment row (`FOR UPDATE`). Rule 10 locks dentists in id order and keeps the tried locks until commit (InnoDB cannot release a row lock early). Deadlock (1213) retried once. Patient insert happens inside the same transaction after the locks; unique-key race → re-select. | Consistent order prevents deadlocks; holding the extra lock briefly is harmless. |
| B10 | Confirm conflict | 409 `slot_unavailable` returns `reason`, fresh `slots` for that date/service/dentist (excluding itself) and `freeChairs` at its time. Requests whose start has passed can only be declined (`startPassed` in the queue). | Most real conflicts are the chair; PRD flow "staff pick another". |
| B11 | Reminders concurrency | Cron takes a MySQL advisory lock (`GET_LOCK('dental_reminders_cron', 0)`); an overlapping run returns `{ skipped: 'already_running' }`. Each row is re-checked before sending; `reminder_sent_at = NOW()` only after a successful send, via `UPDATE … WHERE reminder_sent_at IS NULL`. | Two concurrent runs could otherwise both email before either records it. No 8th table needed. |
| B12 | Cron secret | `CRON_SECRET` unset/empty → 500 `cron_not_configured` (never open). Token compared with `timingSafeEqual` on SHA-256 digests (equal length always). | NF09, PRD API table. |
| B13 | Mail dev mode | SMTP vars unset and not production → log with `[mail:dev]` prefix and report sent; production without SMTP → failure (`emailError` shown, reminder not recorded). CR/LF stripped from to/subject. Nodemailer 10.0.16 (earlier versions have open advisories). Timeouts 10/10/20 s. | Lets QA run locally; never fakes success in production. |
| B14 | Login throttle | In-memory 10 failed attempts / 15 min per IP+email → 429 with `Retry-After`; success clears. Per serverless instance only (cold start resets). | Cheap brake without an 8th table; bcrypt cost 12 remains the main cost. Security agent: note limitation. |
| B15 | Setup week shape | Dentist create/update accept `schedules` rows or a 7-entry `week` (null = off); `PATCH /api/setup/schedules` with `{ dentistId, week \| schedules }` replaces the week (DELETE + INSERT in one transaction); `{ id, startTime, endTime }` edits one row. Deleting a dentist deletes its hours first and rolls back to 409 `in_use` if appointments reference it. | Matches the Phase 3 weekly grid; schedule rows have no inbound FKs. |
| B16 | Small foundation edits | `lib/types.ts` (read DTOs), `lib/validation.ts` (`weekHoursSchema`, `weekToSchedules`, `scheduleReplaceSchema`, `week` on dentist schemas), `lib/http.ts` (`requireStaffApi`, `staffFromRequest`, `parseIdParam`, `parseOptionalJsonBody`), `eslint.config.mjs` ignores `.next-*/**` (per-process dist dirs were being linted). | Additive only. |
| B17 | Test isolation | Every Backend-B integration suite resets `dental_test` in `beforeAll` and again in `afterAll`, so suites that read the seed without resetting (seed-report) still see it. Route handlers are called directly with real `Request`s; only the mail transport is faked (`setMailTransport`). Dates in route tests are computed from today (next Mon–Sat ≥ 2 days ahead). | Real clock in handlers; deterministic data. |
