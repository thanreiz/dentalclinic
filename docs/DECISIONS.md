## Backend-B (API, PRD Phases 4–9 server side)

| # | Topic | Decision | Why |
| --- | --- | --- | --- |
| B1 | Handler auth | Staff handlers call `requireStaffApi(req)` (lib/http.ts), which verifies the same signed `session` cookie as `requireStaff()` but reads it from the `Request`. | `cookies()` from `next/headers` throws outside a Next request scope, so handlers could not be integration-tested directly; behavior in Next is identical. |
| B2 | Error shape | Every error is `{ error: code, message, ... }`; FK RESTRICT → 409 `in_use` with message "In use by existing appointments"; duplicate contact → 409 `duplicate_contact` with message "Contact number already used by another patient". Unknown errors → logged, generic 500. | One shape for the UI; codes for logic, messages for people; no SQL leaks. |
| B3 | Dashboard grid | Shows pending, scheduled, attended, no-show; hides cancelled and declined. `openSlots` uses the shortest service's duration. Pending rows (no chair) appear in the dentist view and in `unassigned` for the chair view. | A cancelled original of a reschedule would otherwise sit next to its replacement; the dashboard has no service picked. |
| B4 | Summary counts | `todayTotal` = grid rows on the date; `pendingCount` = all pending; `tomorrowCount` = scheduled on date+1 (reminder candidates, without the email filter). | PRD Phase 6 wording. |
| B5 | Reports | Only attended/cancelled/no-show rows count; `total` = attended + cancelled + no-show; cancelled excludes rows some other row's `rescheduled_from_id` points to; rate null when attended + no-show = 0. Repeat no-shows are all-time (not month-scoped). | FR15/FR16; Table 3.22 reproduced (10.0 / 20.0 / 14.3%). |
| B6 | Public form vs existing patient | A matching contact number reuses the patient and does **not** overwrite name/email/birthdate from public input. The confirmation goes to the email on file. | Otherwise anyone who knows a patient's number could change their record or redirect their emails. Staff edit details on the patient page. |
| B7 | Public slot grid | `POST /api/requests` also requires the start to be on the Rule 5 grid (hours start + k × `SLOT_INTERVAL_MINUTES`); off-grid → 409 `slot_taken`. Staff bookings may use any time inside hours. | The public API can't book times the form never offers; staff keep flexibility for walk-ins. |
| B8 | Booking window | Public slots/requests: today..today+60 (Manila), else 400. With a staff session `GET /api/slots` allows up to 366 days. | PRD Phase 4; staff may book further ahead. |
| B9 | Rule 9/10 locks | Lock order everywhere: dentist(s) ascending id → chair → appointment row (`FOR UPDATE`). Rule 10 locks dentists in id order and keeps the tried locks until commit (InnoDB cannot release a row lock early). Deadlock (1213) retried once. Patient insert happens inside the same transaction after the locks; unique-key race → re-select. | Consistent order prevents deadlocks; holding the extra lock briefly is harmless. |
| B10 | Confirm conflict | 409 `slot_unavailable` returns `reason`, fresh `slots` for that date/service/dentist (excluding itself) and `freeChairs` at its time. Requests whose start has passed can only be declined (`startPassed` in the queue). | Most real conflicts are the chair; PRD flow "staff pick another". |
| B11 | Reminders concurrency | Cron takes a MySQL advisory lock (`GET_LOCK('dental_reminders_cron', 0)`); an overlapping run returns `{ skipped: 'already_running' }`. Each row is re-checked before sending; `reminder_sent_at = NOW()` only after a successful send, via `UPDATE … WHERE reminder_sent_at IS NULL`. | Two concurrent runs could otherwise both email before either records it. No 8th table needed. |
| B12 | Cron secret | `CRON_SECRET` unset/empty → 500 `cron_not_configured` (never open). Token compared with `timingSafeEqual` on SHA-256 digests (equal length always). | NF09, PRD API table. |
| B13 | Mail dev mode | SMTP vars unset and not production → log with `[mail:dev]` prefix and report sent; production without SMTP → failure (`emailError` shown, reminder not recorded). CR/LF stripped from to/subject. Nodemailer 10.0.16 (earlier versions have open advisories). Timeouts 10/10/20 s. | Lets QA run locally; never fakes success in production. |
| B14 | Login throttle | In-memory 10 failed attempts / 15 min per IP+email → 429 with `Retry-After`; success clears. Per serverless instance only (cold start resets). See S9 for the IP source and per-email bucket. | Cheap brake without an 8th table; bcrypt cost 12 remains the main cost. Security agent: note limitation. |
| B15 | Setup week shape | Dentist create/update accept `schedules` rows or a 7-entry `week` (null = off); `PATCH /api/setup/schedules` with `{ dentistId, week \| schedules }` replaces the week (DELETE + INSERT in one transaction); `{ id, startTime, endTime }` edits one row. Deleting a dentist deletes its hours first and rolls back to 409 `in_use` if appointments reference it. | Matches the Phase 3 weekly grid; schedule rows have no inbound FKs. |
| B16 | Small foundation edits | `lib/types.ts` (read DTOs), `lib/validation.ts` (`weekHoursSchema`, `weekToSchedules`, `scheduleReplaceSchema`, `week` on dentist schemas), `lib/http.ts` (`requireStaffApi`, `staffFromRequest`, `parseIdParam`, `parseOptionalJsonBody`), `eslint.config.mjs` ignores `.next-*/**` (per-process dist dirs were being linted). | Additive only. |
| B17 | Test isolation | Every Backend-B integration suite resets `dental_test` in `beforeAll` and again in `afterAll`, so suites that read the seed without resetting (seed-report) still see it. Route handlers are called directly with real `Request`s; only the mail transport is faked (`setMailTransport`). Dates in route tests are computed from today (next Mon–Sat ≥ 2 days ahead). | Real clock in handlers; deterministic data. |

## Security fixes (Security Fixer, after docs/SECURITY-REVIEW.md)

| # | Topic | Decision | Why |
| --- | --- | --- | --- |
| S1 | Booking abuse caps (H1) | Inside the booking transaction: clinic-wide online requests created in the last hour ≤ `REQUEST_LIMIT_PER_HOUR` (60) and last 24 h ≤ `REQUEST_LIMIT_PER_DAY` (300); then ≤ `REQUEST_LIMIT_PER_CONTACT` (3) **pending** online requests dated today or later per patient (= normalized number). Plus an in-memory per-IP limit, `REQUEST_LIMIT_PER_IP` (5) accepted per `REQUEST_LIMIT_IP_WINDOW_MINUTES` (10), checked before validation and counted only on 201. All → 429 `too_many_requests` + human `message` (IP limiter adds `Retry-After`); `/book` shows the message. 0 disables a cap. | Uses only `appointments` (no 8th table), so the DB caps hold across Vercel instances; the IP limiter is a cheap first brake. Only pending rows count, so a patient with confirmed visits is never blocked. No per-date cap: Rule 1 already bounds a day to its capacity. |
| S2 | Remote seed password (H2) | `resetDatabase` (and `db:reset` before connecting) refuses a non-local host unless `SEED_STAFF_PASSWORD` is set, is not the default and is ≥ 12 chars. Blank env = unset. Remote resets print `(SEED_STAFF_PASSWORD)`, never the value. `db:local` keeps the default in `.env.local` for local convenience, so a remote reset must pass its own password on the command line. | The default is published in the repo; the hosted demo holds panelists' PII. |
| S3 | Post-login redirect (M1) | `safeNextPath` normalizes with `new URL(next, dummy origin)` and checks/returns the normalized path. | Prefix checks on the raw string missed dot segments (`/.//evil.com`). |
| S4 | "Details differ" flag (M2) | A public request that matches an existing number but types a different name/email/birthdate keeps the record (B6) and stores `patient_note` = `[Details differ from patient record: …. Verify before confirming.]` + newline + the patient's own note. `/requests`, `/appointments/[id]` show it as an amber warning (`components/staff/DetailsDifferFlag.tsx`, `lib/patient-note.ts`). Response unchanged (no enumeration oracle). The matched patient row is locked `FOR UPDATE`. | Seven-table constraint: no column for "unverified"; staff need a visible signal before confirming. |
| S5 | DB TLS in production (M3) | `NODE_ENV=production` + non-local host: TLS with `DATABASE_CA_CERT`, `rejectUnauthorized: true` (host name checked), otherwise the pool throws. `\n` escapes and surrounding quotes accepted. Outside production nothing changes (scripts can still use unverified TLS). | Fail closed; the build does not touch the DB (all DB pages are dynamic), so only runtime needs the variable. See docs/DEPLOY.md. |
| S6 | Hosted env file (M4) | Hosted values live in `.env.hosted` (never auto-loaded by Next; ignored by `.env*`). `db:local` warns if `.env.production(.local)` exists. Never keep hosted values in `.env.production*`. | `next start` loads `.env.production.local` automatically. |
| S7 | Security headers (L1) | `next.config.ts headers()` on `/:path*`: CSP (`'unsafe-inline'` scripts, `'unsafe-eval'` + `ws:` only in dev), `frame-ancestors 'none'` + `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, COOP `same-origin`, HSTS 2 years in production; `poweredByHeader: false`. Zod runs `jitless` (`lib/validation.ts`). | Nonce-based CSP would force every page through dynamic middleware; there are no third-party scripts. Zod's `new Function` probe otherwise logs a CSP violation on pages that validate on the client. |
| S8 | Session tokens (L2) | `jwtVerify` with `requiredClaims: ['exp','iat','sub']` and `maxTokenAge` = 8 h. Still stateless (no table): logout clears the cookie only. **To log everyone out, rotate `SESSION_SECRET` on Vercel and redeploy.** | Revocation needs server state (an 8th table or a column); the shared single role and 8 h TTL keep the window small. |
| S9 | Throttle IP source (L3) | On Vercel (`VERCEL` set): `x-vercel-forwarded-for` → `x-real-ip` → first XFF hop. Elsewhere: last XFF hop; Vercel headers ignored. No IP → the request limiter is skipped (no shared `unknown` bucket). Login adds a per-email bucket: 50 failures / 15 min from any IP. All in-memory per instance. | Platform headers can't be spoofed on Vercel; elsewhere the last hop is what the nearest proxy saw. The per-email bucket can lock the login for 15 min (accepted; bcrypt + strong password are the real brake). |
| S10 | Error logs (L4) | Unexpected errors log `safeErrorSummary(err)`: for mysql2 only `code/errno/sqlState` and `sqlMessage` cut before the first quote; never `sql` or params. | mysql2 inlines values into `err.sql`. |
| S11 | JSON bodies (I1, I3) | `readJsonBody` (lib/http) for every JSON route: > 64 KB → 413 `payload_too_large`; non-empty body without `application/json` → 415 `unsupported_media_type`; bad JSON → 400. Empty body allowed only for routes without input. | Defense in depth on top of the Origin check and SameSite. |
| S12 | Small hardening (I4, I6, I7, I9) | Constant cost-12 dummy hash; privacy line under the `/book` consent box; `CRON_SECRET` < 32 chars → 500 `cron_not_configured`; pool `stringifyObjects: true`. | Cheap and clearly beneficial. |
| S13 | Not changed (I2, I5, I8, I10, `__Host-`) | Kept as reviewed: staff pages each call `requireStaffPage()`; `?q=` stays (staff-only, `no-store`); postcss/braces advisories are build/dev-only; dev mail log stays; cookie name stays `session`. | Low value vs. churn (a cookie rename would also break existing sessions and tests). |
| S14 | E2E / load testing | The limits apply to every client, including Playwright on localhost. For automated suites that post many requests, start the server with `REQUEST_LIMIT_PER_IP=0` (and raise or zero `REQUEST_LIMIT_PER_CONTACT` / `_PER_HOUR` if a test reuses one number or floods). Never relax them on Vercel. | Keeps production defaults strict without special-casing localhost. |
